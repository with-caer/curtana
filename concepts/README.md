Curtana is your AI concierge.

The name comes from the Sword of Mercy: A ceremonial blade with a deliberately blunted tip, symbolizing power tempered by restraint. A metaphor for an agent that's deliberately limited for safety.

## Concepts

### Mitigates [the Lethal Trifecta](https://simonwillison.net/2025/Jun/16/the-lethal-trifecta/)

The Lethal Trifecta is a dangerous combination of AI agent capabilities:

1. Access to private data.
2. Exposure to untrusted data.
3. Ability to take action.

Systems like OpenClaw have all three: They'll read email, process attacker-controlled content, and can send messages or run commands. 

This concierge breaks the trifecta by eliminating the ability to take action. It consists of three components:

1. A self-hostable, read-only agent that runs local LLM inference and RAG, but has no ability to take actions.
2. An external gateway that can receive action proposals from the agent, presenting them for human review.
3. An execution service that can execute approved actions, but has no agentic functionality.

### Normalizes Artifacts to Markdown

The read-only agent normalizes all artifacts (e.g., emails and PDFs) to Markdown text, which can then be content-aware chunked for embedding into a local vector index.

### Learns Taxonomies of Artifacts

The read-only agent retrieves artifacts and stores them in local vector databases organized by **taxonomy**. A taxonomy is a named, described collection of artifacts backed by its own database. Each taxonomy has:

- A **name** derived from the source type and source identifier (e.g., `imap-knowledge`, `imap-historical`)
- A **description** generated by the agent that characterizes the kind of content it holds

#### Discovery

Taxonomies are discovered from configured sources. The user configures only the connection to a data source. The agent then queries the source to discover what organizational structures are available.

For IMAP, the agent connects and runs the `LIST` command to enumerate available folders. It presents the discovered folders to the user, who selects which ones to ingest. Each selected folder becomes a taxonomy, named by convention as `{source_type}-{folder_name}` (e.g., `imap-knowledge`, `imap-historical`).

Other source types would follow the same pattern: connect, discover available structure, present options, and create taxonomies from selections. The agent can re-run discovery at any time to surface new folders or sources that have appeared since the last run.

#### Taxonomy Manifest

After discovery and ingestion, the agent persists a **taxonomy manifest**, which is a record of each taxonomy's name, description, and source metadata. This manifest is stored alongside the taxonomy databases and serves two purposes:

1. It provides the descriptions the agent needs for query routing.
2. It records which sources have been discovered and selected, so the agent can detect new sources on subsequent runs.

The agent generates each taxonomy's description by sampling and summarizing a batch of artifacts from that taxonomy after initial ingestion. For example, after ingesting the `imap-knowledge` folder, the agent might summarize a sample of its emails and produce: *"Technical reference material covering cryptography, systems programming, and web development."* The description is regenerated periodically as new artifacts are ingested, keeping it current.

#### Ingestion

Each selected source is ingested into its own taxonomy database. For example, emails in a `knowledge` IMAP folder are ingested into an `imap-knowledge` database, and emails in a `historical` folder are ingested into an `imap-historical` database.

A future enhancement could enable hybrid assignment, where the agent uses LLM inference to reclassify or cross-file artifacts after ingestion.

#### Query Routing

When the agent receives a query, it uses the local LLM to classify the query's intent against the taxonomy descriptions from the manifest. The agent's context includes the name and description of each taxonomy, giving it enough information to route the query to the most relevant collection(s). A query may be routed to multiple taxonomies when it spans categories, with results merged and reranked.

For example:

- `"Tell me about the latest trends in AI."` routes to taxonomies related to historical knowledge.
- `"Tell me about encryption algorithms."` routes to taxonomies related to current knowledge.

#### Configuration

The user configures only data source connections. Taxonomy creation is handled by the agent through discovery.

```toml
[[source]]
type = "imap"
host = "imap.example.com"
port = 143
username = "user@example.com"
password = "..."
```
